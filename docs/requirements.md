# 产品需求

更新日期：2026-09-09

## 定位

doebkweb 是一个不依赖平台推荐和社交机制的个人空间，承担四个职责：

- 个人介绍与公开联系方式
- 自用技术文档知识库
- 个人唱片架与跨页播放器
- 摄影作品与拍摄札记

网站必须保持纯静态输出，无账户、评论、数据库或服务端运行时。

## 页面与路由

| 页面 | 路由 | 核心职责 |
|---|---|---|
| 首页 | `/[lang]/` | 视觉入口和四个主导航 |
| 关于我 | `/[lang]/about/` | 自述与联系方式 |
| 文档 | `/[lang]/docs/` | 列表、日期排序、全文搜索 |
| 文档详情 | `/[lang]/docs/[slug]/` | Markdown 正文、元信息、目录 |
| 音乐 | `/[lang]/music/` | 专辑浏览、搜索、排序和播放 |
| 摄影 | `/[lang]/photos/` | 照片墙、时间线、札记搜索和 Lightbox |
| 404 | `/[lang]/404/` | 错误说明与返回首页 |

根路径 `/` 重定向到 `/zh/`。当前支持 `zh` 和 `en`，语言前缀始终保留。

## 首页体验

- 背景跟随全站明暗主题，页面中只保留必要内容。
- `doebkblcya` 是唯一主标题，初始状态水平居中并占据主要视觉面积。
- 人物画作位于前景，以轻微 3D 视差与标题形成遮挡关系。
- 初始状态隐藏导航；下拉、上滑、键盘或页面任意非交互区域点击后一次完成动画并显示“关于我、文档、音乐、摄影”。
- 反向操作可收回；动画可中断，不因连续输入累积多个队列。
- 展开后人物不得遮挡标题和导航，导航必须可点击。
- 桌面和手机采用独立终态比例；小屏使用安全区和动态视口单位。
- 首页不添加年份、Archive、介绍句、操作说明等辅助文案。
- reduced-motion 用户直接进入可操作终态。

## 站内页面

### 视觉系统

- 所有站内页使用同一套展览画册语言：编辑型标题、无衬线正文、等宽元数据、直角边界和 1px 结构线。
- 全站浅色主题为纸白画布，深色主题使用纯黑。
- 界面减少玻璃、胶囊和悬浮卡片阴影，视觉层级主要依靠字号、栅格、留白和边界。
- 中英文字体必须由项目自托管，中文不得依赖不可控的默认字体回退。

### 导航与主题

- 桌面端显示固定左侧栏；宽度不大于 640px 时改为汉堡抽屉。
- 首页隐藏侧栏、汉堡按钮与播放器入口，使用首页自己的导航。
- 当前页面有明确导航状态。
- 主题支持浅色、深色和跟随系统，并在刷新和客户端导航后保持。
- 设置面板负责语言与主题选择。

### 文档

- 文档使用 Markdown 和类型安全 frontmatter。
- 列表默认按日期从新到旧，支持反向排序。
- Pagefind 提供当前语言路由内的全文搜索和键盘操作。
- 详情页使用 Shiki 双主题代码高亮；表格在窄屏横向滚动。
- h2/h3 生成目录 rail；小屏可以隐藏目录，正文仍可独立阅读。
- 文档正文不做机器翻译。

### 音乐

- 专辑和曲目来自单一 JSON 数据源。
- 支持按专辑名或艺术家搜索、排序。
- 播放器支持播放/暂停、上一首/下一首、音量、播放列表和专辑札记。
- 播放器保留黑胶与唱臂的具象表达，外围控制使用与站内一致的直角、细线和编辑排版。
- 播放器不设置独立关闭按钮；点击面板外或按 Escape 收起。未选择专辑时，唱片架入口占满工具区。
- 手机端播放控制独占一行，播放列表、音量和唱片架在下一行等宽排列，唱臂不得遮挡文字与操作区。
- 切换站内页面时音频不中断，当前播放器状态不重建。
- 切换语言后，持久化播放器的文案和唱片架链接必须同步到当前语言。
- 曲序由 `trackNo` 决定，不依赖 JSON 数组书写顺序。
- LRC 字段可以存在；歌词展示 UI 不是当前必需功能。

### 摄影

- 数据来自单一 JSON 文件，默认按拍摄日期倒序。
- 支持照片墙和时间线两种视图，视图选择本地记忆。
- 可按札记搜索。
- Lightbox 支持前后切换、背景关闭、Escape 和方向键。
- 图片失败时显示明确错误状态，不残留上一张图片。

### 关于我

- 正文来自 `src/data/about.ts`，不再使用 Content Collections。
- 内容保持简洁，只包含名字、定位语、自述和公开联系方式。
- 正文不随 UI 语言自动翻译。

## 内容与资源

- 技术文章放在 `src/content/docs/`。
- 小型站点素材放在 `public/`；音乐、封面、摄影原图和缩略图放 R2。
- 媒体数据修改通过 `pnpm media` 工作流完成。
- 不在 Git 中提交凭证、原始媒体、构建产物、`tmp/` 或 `_r2-upload/`。
- 所有公开文档必须移除真实密钥、内网地址、私人联系方式和本机身份路径。

## 技术与质量要求

- Astro 静态构建必须成功，Pagefind 索引包含 zh/en 文档页。
- ClientRouter 只用于客户端导航和播放器持久化，不承担全局页面动画。
- 只有 audio 和 VinylPlayer 可以 `transition:persist`。
- 页面级交互必须有明确的挂载与销毁生命周期。
- 键盘可完成核心导航与弹窗操作；每页必须有唯一标题和有效 `<title>`。
- 所有动效遵守 `prefers-reduced-motion`。
- 手机端不能出现水平溢出、不可达按钮或被浏览器工具栏遮住的固定内容。
- SEO 至少包含 canonical、Open Graph 基础信息和 sitemap。

## 明确不做

- 登录、评论、点赞、统计后台和数据库
- 文档分类页、归档页、独立搜索页
- 自动翻译正文
- 纯装饰性的滚动视差、拖拽或全站方向滑页
- RSS、标签云、热力图、系列文章导航
- 迷你唱片到播放器面板的跨元素 morph

## 验收

每次涉及导航或交互的发布至少检查：

1. 首页直接访问、展开和收回。
2. 首页进入任一内页再返回，DOM 和事件不重复。
3. 浏览器前进/后退。
4. zh/en 页面跳转和主题保持。
5. 手机与桌面布局。
6. 播放中的音频跨页保持同一实例。
7. `pnpm exec astro check`、`pnpm build`、`git diff --check`。
